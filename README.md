# orbit-client

Собственный пакетный клиент-бот для DarkOrbit (Java 21). Личный проект, не для распространения.

Статус: готовы разведка протокола, сниффер и генератор кода протокола (этапы 0–2); идёт этап 3
(вход на сайт, игровое подключение, хранилище секретов).
План работ — `docs/PLAN.md`, описание протокола — `docs/recon/`.

## Что нужно для разработки

- JDK 21 (Temurin). На macOS: `brew install --cask temurin@21` или распаковать сборку в
  `~/Library/Java/JavaVirtualMachines`.
- Для обновления протокола дополнительно: Python 3, git и JPEXS FFDec
  (zip с https://github.com/jindrapetrik/jpexs-decompiler/releases, путь к `ffdec.jar` — в `FFDEC_JAR`,
  по умолчанию `~/tools/ffdec-26.4.0/ffdec.jar`).

## Сборка и тесты

```sh
export JAVA_HOME=$(/usr/libexec/java_home -v 21)   # macOS
./gradlew build
```

Классы пакетов (`orbit.protocol.gen`, ~1400 шт.) генерируются при сборке из
`reference/protocol/packets-*.json` и в git не хранятся.

Тесты протокола:
- каждый пакет заполняется случайными данными → кодируется → раскодируется → кодируется снова,
  байты должны совпасть;
- все пакеты из записанных сессий (`recordings/*.dorec`) раскодируются и кодируются обратно
  байт в байт. Записи лежат только локально (в них данные аккаунта); без них тест пропускается.

## Сниффер

Показывает живой трафик официального клиента с названиями и полями пакетов и пишет сессию в файл.

```sh
scripts/sniff-session.sh          # запускает сниффер и DarkOrbit Client.app через него
```

- Журнал: `logs/sniffer.log`, записи: `recordings/session-*.dorec` (`sessionID` замаскирован).
- Отчёт по записям: `sniffer/build/install/sniffer/bin/session-report recordings`
  (`--show MoveRequest,AddBoxCommand` — показать примеры пакетов с полями).

## Аккаунты и хранилище секретов

Логины, пароли и сессии сайта (`dosid`) хранятся в зашифрованном файле `local/vault.bin`
(AES-256-GCM, ключ из мастер-пароля). Мастер-пароль спрашивается в терминале; для запуска без
консоли (VPS) его можно передать переменной `ORBIT_MASTER_PASSWORD`. Пароли, `dosid` и
`sessionID` в журналах заменяются на `***`.

```sh
./gradlew :secrets:installDist :game:installDist
V=secrets/build/install/vault/bin/vault
$V add main                       # спросит логин, пароль и (необязательно) dosid
$V import main creds.txt          # или взять логин и пароль из файла, затем удалить файл
$V set-dosid main                 # если сайт просит капчу: dosid из браузера
$V list
```

Бот сначала входит по сохранённому `dosid` и только если он устарел — по паролю, а новый `dosid`
сохраняет в хранилище. Частые входы по паролю заставляют сайт требовать капчу.

Проверка входа и игрового подключения (бот ничего не делает в игре, только держит связь):

```sh
game/build/install/game-check/bin/client-profile recordings   # один раз: состояние UI клиента из записей
game/build/install/game-check/bin/game-check --account main --seconds 60
```

После входа бот отправляет те же пакеты, что официальный клиент, в том же порядке и с теми же
паузами (`docs/recon/STAGE3.md`). Раскладку окон, таблицу клавиш и строку `ReadyRequest` клиент
берёт из своего локального состояния, поэтому бот повторяет их из записи сниффера этого аккаунта:
`client-profile` сохраняет их в `local/client-profile.json`. Без профиля эти пакеты не отправляются.

Исходящие пакеты официального клиента в начале сессии:
`sniffer/build/install/sniffer/bin/session-report --upstream 20 recordings`.

## Обновление протокола после патча игры

Когда игра обновилась, бот (и сниффер) сообщит: «Версия протокола устарела… запустите регенерацию».

```sh
scripts/update-protocol.sh        # macOS / Linux
scripts\update-protocol.ps1       # Windows (PowerShell)
```

Скрипт сам скачает новый `main.swf`, декомпилирует нужные пакеты, разберёт их, покажет, какие
пакеты добавились/удалились/изменились, сгенерирует классы, соберёт проект и прогонит тесты.
Обычно это занимает меньше минуты. Если `main.swf` не изменился, скрипт просто сообщит, что
протокол актуален (`--force` — перегенерировать всё равно).

Если после обновления падает тест на записанном трафике — старые записи сделаны на прошлой
версии протокола: удалите `recordings/` и снимите новую сессию сниффером.

Если скрипт пишет, что структура клиента изменилась (не найдены пакеты или константы), значит,
разработчики игры поменяли устройство клиента — нужен ручной разбор.
