# Этап 0. Отчёт разведки

Дата: 2026-11-09. Источники: официальный `main.swf`, декомпилированный JPEXS FFDec 26.4.0,
инструменты ProjectOpenOrbit, Electron-клиент `DarkOrbit Client.app`.
Описание составлено своими словами по результатам анализа. Декомпилированный код в репозиторий
не входит (лежит локально в `reference/decompiled/`, исключён из git).

## 2. Транспорт

- Обычный TCP-сокет Flash (`flash.net.Socket`), **без TLS и без шифрования**.
- Порядок байтов — **big-endian**.
- Адрес сервера: для каждой карты берётся из `<dynamicHost><basePath>xml/maps.php`, поле
  `gameserverIP` вида `host:port`. Если порта нет — 5001.
  Пример (кластер 22): `gameserver-22-01-public.prod.darkorbit.com:6003`. Все хосты кластера
  указывают на один IP (`170.33.12.50`), различаются портами 6001–6007 (2 арены + 5 игровых).
- Flashvar `localGS` может переопределить сервер для всех карт (отладочный механизм клиента).
- Сразу после установления соединения клиент шлёт **один байт `0x00`**.

## 3. Формат кадра

### Исходящие (клиент → сервер)
```
[len: 3 байта, uint24 BE] [packetId: int16 BE] [поля пакета…]
```
`len` — длина всего, что после заголовка (id + поля). Сжатия нет.

### Входящие (сервер → клиент)
Тот же 3-байтовый заголовок длины. Дальше тело:
- если первые два байта **не** `FF FF` — это один пакет без сжатия: `[packetId int16][поля]`;
- если `FF FF` — сжатый конверт (только если клиент заявил сжатие в `LoginRequest`):
  - magic (4 байта): `DOB3` — блок из нескольких пакетов; `DOL4` — старый формат, один пакет;
  - размер распакованных данных (uint32 BE), CRC-32 распакованных данных (uint32 BE);
  - данные в формате **LZ4 block** (стандартный: токен, литералы, смещение 2 байта LE, match ≥ 4);
  - конверт `DOB3` после распаковки — последовательность `[len uint24][пакет]`, каждый пакет
    обычный `[packetId][поля]`; вложенных `FF FF` быть не может;
  - лимит распакованного размера — 3 МБ; при ошибке клиент рвёт соединение.

Бот может заявить сжатие (как настоящий клиент) — это нужно и для правдоподобия, и для
экономии трафика. Реализация LZ4-распаковки в Java тривиальна (есть `lz4-java` или своя ~80 строк).

## 4. Кодирование полей

Примитивы `IDataOutput`: `writeInt` (int32), `writeShort` (int16), `writeByte`, `writeBoolean` (1 байт),
`writeDouble` (float64), `writeFloat` (float32), `writeUTF` (uint16 длина + UTF-8).

**Запутывание:** почти каждое целое поле перед записью циклически сдвигается (rotate) на
константу, своя для каждого поля каждого класса. Int — rotate по 32 битам, short — по 16 битам.
Чтение делает обратный сдвиг. Константы меняются от сборки к сборке — именно поэтому протокол
нужно перегенерировать после каждого патча.

Составные части:
- **подмодуль** (вложенный пакет): пишется как полноценный пакет со своим id; вместо отсутствующего
  — `int16 0`. Реальный тип определяется по id (полиморфизм через фабрику);
- **массив**: длина (int/short/byte), затем элементы — примитивы (тоже со сдвигом) или подмодули;
- **наследование**: потомок пишет свой id, затем поля родителя (`super.write`), затем свои.

`ModuleFactory` — реестр «id → класс», `HandlerLookup` — «id → обработчик» на стороне клиента.

## 5. Последовательность входа

1. HTTP: вход на сайт, страница игры с flashvars (`userID`, `sessionID`, `factionID`, `dynamicHost`,
   `basePath`, `pid`/instance и др.). Детали входа на сайт — этап 3.
2. Клиент грузит `maps.php`, выбирает `gameserverIP` для текущей карты.
3. TCP-подключение → байт `0x00`.
4. → `VersionRequest` (id 666): хэш протокола.
5. ← `VersionCommand` (id 667): `version`, `equal`. Если `equal = false` — сервер считает клиент
   устаревшим → **это и есть наш детектор «протокол устарел, запустите регенерацию»**.
6. → `LoginRequest` (id 7): `userID`, `factionID`, `sessionID`, `version = "do-lz4-block-v3"`,
   `instanceId`, `isMiniClient` (true для «клиентской» платформы).
7. ← `LoginResponse` / инициализация корабля и карты (`ShipInitializationCommand` и др.) — уточнить
   по живому трафику на этапе 1.
8. До завершения входа клиент отправляет только `VersionRequest`, `LoginRequest`,
   `KillScreenRepairRequest`, `ChannelCloseRequest`; остальное складывает в очередь.
9. Дальше `KeepAlive` (id 2, поле `MouseClick: boolean`) каждые **15 с**.

Есть также `LegacyModule` — строковые команды старого протокола (`"a|b|c"`), используются для части
действий; разбор по живому трафику.

## 6. Пакеты (JSON)

Файл: `reference/protocol/packets-2026-11-04.json` — **1374 пакета**, все id уникальны.
Получен upstream-парсером `darkorbit-netcode-parser` без изменений (`tools/recon/run_parser.py`).

| Тип | Кол-во |
|---|---|
| `*Command` (сервер → клиент) | 780 |
| `*Request` (клиент → сервер) | 321 |
| `*Module` (вложенные структуры) | 236 |
| прочие имена | 37 |

Проверка (`tools/recon/validate_packets.py`): для каждого класса число примитивных записей в
`write()` сверено с JSON — расхождений нет (два найденных отличия оказались ошибками самой проверки).
Не разобран 1 файл — `CannonType`, это перечисление, не пакет.

Ограничения парсера, которые учтём в своём генераторе:
- в JSON нет явного направления пакета (определяем по суффиксу имени и по `HandlerLookup`);
- разбирается только `write()`; `read()` считаем симметричным — **подтвердим тестами на живом трафике**;
- ветки `if/else` с подмодулями сведены к «submodule» — для полиморфных полей нужен базовый тип.

`darkorbit-netcode-generator` — заготовка на 16 строк, функциональности нет. **Генератор пишем свой на Java** (этап 2).

## 7. Что важно для безопасности и `humanize`

- `CaptchaTriggerCommand` / `CaptchaCollectRequest` / `CaptchaResolvedCommand` — **внутриигровая капча**
  (ящики на карте). Бот обязан её распознавать и решать или останавливаться — иначе бан.
- `LogBoxInformationRequest` — пакет с контрольными суммами (adler32/crc32, `classId`, `pixelColor`…),
  похож на проверку целостности клиента. В текущем коде клиента **не отправляется** (есть только в
  фабрике) — проверить по живому трафику, не шлёт ли его сервер по запросу.
- Клиент шлёт аналитику на отдельный канал (`EventStreamClient`: подключение, разрывы, ошибки).
  Пакетный бот её не шлёт — это потенциальное отличие от настоящего клиента. Оценить на этапе 1.
- Признак `isMiniClient` в `LoginRequest` и `MouseClick` в `KeepAlive` — сервер видит тип клиента
  и наличие кликов мыши. Бот должен выставлять их как реальный клиент.

## 8. Способ MITM для `DarkOrbit Client.app` (без правки swf)

Клиент — Electron 2.8.0 (Kaiserdj, open source) с PepperFlash. Запускается с
`ignore-certificate-errors`, понимает `--dosid`, `--url`, `--dev`.

**Выбранный способ:** перенаправить DNS-имена игровых серверов на `127.0.0.1`.
Сниффер слушает те же порты (6001–6007…) локально и пересылает трафик на настоящий IP,
расшифровывая/распаковывая по пути. Варианты перенаправления:
1. Chromium-флаг при запуске: `--host-resolver-rules="MAP *.prod.darkorbit.com 127.0.0.1"`
   (без sudo, без правки системы, только этот процесс). **Проверить первым на этапе 1** — что
   PepperFlash-сокеты используют резолвер браузера.
2. Если (1) не сработает — записи в `/etc/hosts` (macOS) / `hosts` (Windows) для 7 хостов
   кластера (нужен sudo, обратимо).
3. Запасной: подмена `gameserverIP` в ответе `maps.php` через HTTP-прокси (`--proxy-server`) —
   клиент уже игнорирует ошибки сертификатов.

Flash перед подключением запрашивает socket policy (`<policy-file-request/>`) — сниффер будет
прозрачно пересылать его на настоящий сервер.

Альтернатива для Windows: в клиенте есть `darkDev/packet_dumper.py` (Frida-хук внутри PepperFlash,
снимает пакеты уже в виде объектов). Для macOS не поддерживается — как основной путь не берём.

## Как воспроизвести

```sh
# 1. скачать swf
D=reference/client/$(date +%F); mkdir -p $D
for f in preloader loadingscreen main; do
  curl -sSA Mozilla/5.0 -o $D/$f.swf https://darkorbit-22.bpsecure.com/spacemap/$f.swf; done
# 2. декомпилировать
java -jar ~/tools/ffdec-26.4.0/ffdec.jar -format script:as -export script reference/decompiled/<ver>/main $D/main.swf
# 3. распарсить
python3 -I tools/recon/run_parser.py tools/external/darkorbit-netcode-parser/src \
  reference/decompiled/<ver>/main/scripts/net/bigpoint/darkorbit/com/module reference/protocol/packets-<ver>.json
python3 -I tools/recon/validate_packets.py reference/protocol/packets-<ver>.json \
  reference/decompiled/<ver>/main/scripts/net/bigpoint/darkorbit/com/module
```
Полное время — около 2 минут. В этап 2 это превратится в один скрипт `update-protocol`.
