# План работ

Статусы: `[ ]` не начато, `[~]` в работе, `[x]` готово и подтверждено пользователем.
После каждого этапа — остановка, демонстрация, подтверждение.

Зафиксированные решения:
- Запуск где угодно: Windows VPS (24/7, headless), обычный Windows-ПК, Мак. GUI и headless —
  равноправные режимы на обеих ОС; оба проверяются на Windows и на маке.
- Сервер тестов — GE1, отдельный запасной аккаунт, без 2FA.
- До 5 аккаунтов в одном процессе, у каждого необязательный прокси (SOCKS5/HTTP).
- Интерфейс, логи, README — на русском. Код и комментарии — на английском.
- Только для личного использования. Из DarkBot берём факты и логику, код целиком не копируем.
- Трафик снимаем с официального `DarkOrbit Client.app`, по возможности без правки swf.
- Код и бинарники AstraBot не используем. `reference/astra-config.json` — только справочник опций.
- .dmg без подписи.

- [~] 3.2 Прокси на аккаунт (HTTP и игровое TCP-соединение).
      *Сделано (2026-11-10):* свой коннектор SOCKS5 (RFC 1928/1929, имя хоста разрешает прокси) и HTTP
      CONNECT (Basic); тип без схемы определяется сам. Сайт и картинки мини-карты идут через локального
      посредника на 127.0.0.1, у каждого аккаунта свой (встроенный SOCKS в Java сам разрешает имя — утечка
      DNS; логин SOCKS в Java глобальный; Basic для туннелей в Java выключен). Проверка перед каждым входом:
      нет прокси — нет входа, напрямую бот не подключается. `vault set-proxy`, `orbit proxy-check`, прокси и
      внешний IP в шапке аккаунта. У AstraBot публичных описаний нет (в конфиге только `respectProxyData`,
      `showProxyInfo`); у DarkBot своего прокси для аккаунта нет (`USE_PROXY` — локальный помощник Kekka для win7).
      Проверка прокси — TLS-рукопожатие с www.darkorbit.com (сертификат и имя): открытый туннель ничего не
      доказывает. Проба 2026-11-10 на ~900 бесплатных прокси: 47 подменяли сертификат (MITM), ещё ~10
      принимали любой CONNECT и молчали; сквозь проходили единицы (10–20 с задержки, policy GE1 отвечает).
      *Проверено вживую (2026-11-10 21:56):* `game-check --account main` (ru1) через бесплатный SOCKS5 —
      проверка прокси, вход по паролю (старый dosid устарел), карта 2-6, 2 мин онлайн, 942 пакета, без
      ошибок; секретов в логе нет. Бесплатные прокси живут минуты: из ~900 сквозь проходят единицы.
      Риск: игровой поток без шифрования — владелец прокси видит sessionID; нужен свой/платный прокси.
      *Два аккаунта одновременно (2026-11-11):* main (ru1) через SOCKS5 и second (int1) через HTTP, у
      каждого свой внешний IP (`proxy-check` обоих в одном процессе), оба по 3 мин в игре, без ошибок; у
      second бесплатный HTTP-прокси оборвал соединение через 2,5 мин — бот переподключился через него за 5 с.

## Режим «только карта»: срезанный верх в менеджере (2026-11-17)

**Почему.** Карта всегда 1,6 : 1 (21 000 × 13 100). Под неё в окне остаётся место: окно минус заголовок (~28 точек) и
полоса вкладок (~30 точек). В «только карта» карта закрывает это место целиком, без полей (`MinimapPanel.projection`,
`Math.max(sx, sy)`):
- место ровно 1,6 : 1 — карта целиком, ничего не срезано;
- место шире 1,6 : 1 — карта растягивается по ширине, лишнее срезается поровну сверху и снизу (случай пользователя);
- место уже 1,6 : 1 — срезаются бока.

**Когда.** Зависит только от формы окна. Заголовок и вкладки — постоянные ~58 точек высоты: чем меньше окно, тем
большую долю они съедают. Пример: окно 640 × 430 → место 640 × 372 (1,72 : 1) → карте нужна высота 400, 28 точек
срезаны, по 14 сверху и снизу. На большом окне срез почти не виден.

**Почему кажется, что из-за нескольких аккаунтов.** Окно одного аккаунта (`MainWindow`, запуск бота) подгоняет
высоту под карту (`fitToMap`). Менеджер (`ManagerWindow`, несколько аккаунтов) — нет. На вкладке «Все» карты
вписываются целиком, там среза нет. Вкладки и так в один ряд (`SCROLL_TAB_LAYOUT`), не переносятся.

**Что не подходит (пользователь):** поля по краям; срез любой части (верх, низ, бока, «камера за кораблём»);
подгонка окна, заметная при изменении размера. Вариант без автоматики — пункт меню
«Подогнать окно под карту» — допустим, но нужна автоматическая подгонка.

**Сделано (выбор пользователя):** менеджер подгоняет высоту окна под карту в спокойные моменты — при включении «только
карта», при переходе на вкладку аккаунта, при запуске (`ManagerWindow.fitAtQuietMoments` → `MainWindow.fitOnce`), и
никогда, пока край окна тянут руками. Растянул окно сам в другую форму — верх может снова срезаться до следующего
переключения вкладки или режима.

## Нагрузка программы (2026-11-16)

- [x] Утечка памяти окна: Java2D на macOS (JDK 21) рисует через Metal, и при нашей карте графическая память
      (IOAccelerator) росла на ~300 МБ в минуту и не освобождалась даже сборкой мусора — за несколько часов кончалась
      вся память мака (macOS жаловалась на память, программа зависала). Через OpenGL память стоит на месте.
      Скрипт запуска передаёт `-Dsun.java2d.metal=false` (`app/build.gradle.kts`).
- [x] Отрисовка карты: фон (заливка, картинка игры, затемнение, сетка, рамка, большое название карты) рисуется один раз
      в картинку и заново — только при смене размера, карты или фона; время сессии — вживую. Карточки — простые
      прямоугольники (скругление 0), метки обрезаются по прямоугольнику. Было 33–37 % ядра и ~835 МБ, стало 26–28 % и
      ~600 МБ (повтор записи, одно окно); вид не изменился.
- Замер на двух аккаунтах с открытой картой: сами аккаунты (`game-*`, `bot-loop`) — ~1,7 % ядра и ~45 МБ данных на
  оба, окно — ~30 % ядра и ~550 МБ. Каждый следующий аккаунт добавляет ~0,5–1 % ядра и ~20–30 МБ; окно стоит одинаково
  (рисуется только открытая вкладка; во «Все» — все карты сразу).
- Свёрнутое окно: ~2 % ядра вместо ~28 %, боты работают в полную силу (за минуту ни одно ожидание потока не опоздало
  больше чем на 50 мс — macOS программу не усыпляет); память не освобождается (~600 МБ), но и не растёт. Мак не должен
  уходить в сон.
- AstraBot для сравнения (по устройству, не замер): exe GraalVM native-image (без JIT), своя копия программы с окном
  на каждый аккаунт; у нас одна программа на все аккаунты.
- [x] Утечка шрифтов на Windows (VPS, 2026-11-16): программа за час дошла до 3,6 ГБ (позавчера ~500 МБ). В куче —
      517 000 `CompositeFont` с кэшами символов (>2 ГБ, мягкие ссылки — при потолке кучи 12 ГБ их почти не чистит).
      Базовый шрифт FlatLaf на Windows — составной с запасными, и каждый `deriveFont` в другое начертание делает новый
      составной шрифт; `Hud.font` так делал на каждом кадре (плашки бустеров, заголовки карточек — профиль JFR).
      Теперь шрифты Hud делаются один раз и хранятся. AstraBot для сравнения — ~95 МБ на аккаунт.
- [ ] Можно ещё: потолок кучи и простой сборщик мусора (~−100 МБ) — после замера пика на 5 аккаунтах; лишние буферы

## Календарь входа (2026-11-20)

Награда календаря входа (сейчас — календарь Mimesis 11–25.11) за пропущенный день теряется. AstraBot отмечает день
запросом к сайту сразу после входа (`flashAPI/dailyLogin.php?doBook=1`, метод `claimDailyLoginRewards`, без настройки);
DarkBot — плагином: DmPlugin `CalendarBonus` (окно календаря в игре, кнопка «Забрать», до 3 попыток; на CARNAGE выключен,
в профиле инвоков включён) или PikaPika `DailyLogin` (запрос к сайту раз в 24 ч). Официальный клиент в наших записях
от 09.11 игровых пакетов календаря (`DailyLoginRewardDayRequest`, `DailyLoginClaimTodayRequest`) не слал.

- [x] Сделано как у AstraBot: `orbit.auth.DailyLogin`, `OrbitMain.watchCalendar` — через 30–90 с после входа и после
      каждой полуночи по серверу (Europe/Berlin) запрос через прокси аккаунта; отмеченный день — в
      `local/calendar.properties`; ответ не 200 — повтор через 30 мин. Галочка «Календарь» в окне аккаунта (по
      умолчанию включена).
- [ ] Проследить и проверить вживую:
      - в журнале строка «Календарь входа: день … отмечен на сайте — ответ: …» — записать сюда, что отвечает сайт, и
        научить бота отличать «награда получена» / «уже получена» / ошибку (сейчас день отмечен при любом ответе 200);
      - в игре (окно календаря) день действительно отмечен и награда пришла — на одном аккаунте, затем на всех;
      - после полуночи по серверу у работающего бота день отмечается снова, без перезапуска;
      - выключенная галочка — запроса нет;
      - если сайт день не отмечает — запасной путь: игровые пакеты `DailyLoginRewardDayRequest` /
        `DailyLoginClaimTodayRequest` (сначала записать снифером, шлёт ли их клиент при открытии календаря).
